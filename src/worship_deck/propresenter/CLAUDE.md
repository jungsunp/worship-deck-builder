# ProPresenter builder — primary target

Loaded when you work under `src/worship_deck/propresenter/`. **Read
`docs/propresenter-architecture.md` first** — the protobuf primer, the generation-flow and `.pro`
anatomy diagrams, and the module map. The *why* behind every rule below is in
`docs/propresenter-generator-design.md`.

- **Ground-up, not template mutation.** `build()` serializes a fresh `rv.data.Presentation` from `ServiceData` each week — no landmark detection, no index arithmetic. Each `fill_*` appends its cues plus one `CueGroup` in service order, so the call order in `build()` *is* the liturgy. Fixed wording lives in `content.py`, dumped verbatim from `master.key` — never composed or "corrected".
- **Protobuf bindings.** `proto/*.proto` is the vendored, unofficial schema pinned to PP 21.4 (`proto/SOURCE.md`), verified to open on the church's 18.4 (#191) — re-vendor only if a generated deck fails to open. `pb/*_pb2.py` is generated by `scripts/gen_proto.sh` and git-ignored. The `from . import pb` + `# isort: off` import order is load-bearing, and `pipeline.run` imports this package lazily because CI has no bindings — keep both.
- **Never write** (each silently breaks the deck in PP): `PresentationSlide.transition` / `Presentation.transition` (#174 — worship uses PP's global cut), `Fill.backgroundEffect` (crashes 21.4; backdrops are pre-blurred images, #224), `Presentation.arrangements` (#176 — groups don't nest), `SCALE_BEHAVIOR_SCALE_FONT_DOWN` (shrinks to one unwrapped line; fit at authoring time instead). Every cue must sit in a `CueGroup` — `serialize` refuses orphans.
- **Elements are front-to-back** (`elements[0]` is the topmost layer); the style builders compose back-to-front and reverse.
- **Keying:** sung-lyric slides, song banners and blank separators are backed with `styles.CHROMA_GREEN` (`#81D654`, #192) so the ATEM keys them over the camera; full-screen sections stay opaque navy.
- **The look is baked in `styles.py`** — the format has no theme reference. To change it, have the operator hand-restyle a generated `.pro` and read the numbers back out of it (#178 round 3); a markup beats a description. After any type-scale, inset or font change, audit a **freshly generated** deck: `python scripts/audit_pro_layout.py <deck.pro>`. A font carries three measured constants (`scripts/measure_advance.swift`), and a new face must be installed on the church mini — PP substitutes silently.
- **Seeing what PP renders:** `python scripts/make_pro_demo.py --run YYYY-MM-DD [--bundle]`, then PP's local HTTP API thumbnails (design doc, "Seeing what ProPresenter actually renders"). PP caches a file it has read — write a new filename each round.
- **Build handoff bundles from the main checkout.** `.probundle` entry names are absolute source paths, and PP silently skipped media under a hidden `.claude/worktrees/…` path on import (#191).
- **Glossa is a machine-local Prop** — the generator writes nothing for it (#177).
